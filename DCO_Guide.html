What the creative team should hand off

1. Layered source / master template
Innovid's knowledge base specifically calls out editable PSD, Google Web Designer or After Effects files depending on the execution. For display, finalized designs are recommended as layered PSDs.
2. Reference comps
JPG/PNG/PDF examples showing the intended finished state, hierarchy, spacing, animation frames and edge cases. These are visual instructions, not necessarily the production ad itself.
3. Clean image assets
High-quality image files with dynamic text/price/legal kept separate. Innovid lists JPG/TIFF for source imagery, while dynamic display templates support SVG, PNG and JPEG assets.
4. Logos, product art and fonts
Vector logos such as AI/EPS or high-resolution PNG; relevant fonts supplied separately. Innovid also recommends limiting display creative to a small number of font files because fonts contribute to file weight.
5. Copy + offer data
A structured feed or matrix containing headlines, offers, CTA, market name, legal IDs and other values. Innovid accepts XML, CSV, Google Sheets, JSON and API feeds.
6. Mapping / decision rules
Document what stays constant, what changes, which data signal controls it, fallback behavior, character limits and legal dependencies.
7. Video / audio when applicable
Innovid lists MOV/MP4 for source video; dynamic video guidance prefers MP4 and consistent format, frame rate, duration/aspect. WAV is used for dynamic audio.

How the DCO Builder maps to the vendor handoff

Your Builder already captures many of the right planning fields. It should be thought of as the creative specification / source-of-truth layer. Innovid may transform those fields into its production template and data-feed structure rather than ingesting the Builder CSV exactly as-is. The Builder currently includes generated filenames, execution/creative version, CE-Code, channel, size, creative brief, image direction, supporting copy, message priorities, market/ZIP, offers, legal and strategy fields.

CE-Code is the Creative Execution Code: it replaces the older Version Code terminology. The human-readable Creative Version describes the route; CE_Code is the stable machine-safe identifier used for filenames, exports and vendor handoff.
The Builder is doing something valuable: it separates the human creative decision from the machine-friendly identifiers and filenames. That is exactly the kind of discipline DCO needs. The next step is to connect each record to a real asset library and explicit field mapping for the vendor build.
File types: what is actually useful

Design / source

PSDGWDAE

Editable source used to understand layers, spacing, animation and construction. Innovid specifically calls these out in its dynamic asset requirements.

Images / logos

JPGPNGSVGTIFFAIEPS

Use clean, high-quality assets. For dynamic display, keep image types and dimensions consistent for a given placeholder.

Data / copy

CSVJSONXMLGoogle SheetAPI

Structured fields supply dynamic values and asset URLs. This is where message, offer, market and legal matrices become programmatic.

Build it this way, not that way

✓ Better for DCO

  • Layered source file with clearly named frames/layers
  • Hero image separated from headline and offer
  • Long-copy and short-copy edge cases designed up front
  • Consistent dynamic image dimensions and file types
  • Offer, market and legal values in structured fields
  • Reference comps for each major size family
  • Clear rules for what is fixed, dynamic, optional and required

✕ Harder for DCO

  • Only flattened JPGs with every message baked into pixels
  • One huge Photoshop file with unlabeled layers
  • Different crop/aspect behavior for every dynamic image without rules
  • Price or legal permanently embedded into hero photography
  • Copy supplied only in emails or comments instead of structured data
  • No fallback for smaller units or unusually long market names
  • Assuming the vendor will infer which claim belongs to which audience
Quick glossary
DCO — Dynamic Creative OptimizationUsing data and rules to personalize and optimize creative elements and messages.
Dynamic assetAn image, video, text, audio or other element that can change between versions.
TemplateThe structural ad build that controls layout, animation and how dynamic elements behave.
FeedStructured data supplying values or asset URLs used by the creative.
Decision ruleThe logic that connects a data condition to a specific creative component or version.
Ad serverTechnology that serves and tracks digital ads.
ProgrammaticAutomated digital-media buying using technology and data.
DSPDemand-Side Platform used by media buyers to purchase programmatic inventory.
CTVInternet-connected television viewing through smart TVs and streaming devices.
ImpressionOne recorded instance of an ad being served.
CTACall to Action, such as Shop Plans or Learn More.
FallbackThe approved default used when data is missing or a dynamic condition cannot be met.
